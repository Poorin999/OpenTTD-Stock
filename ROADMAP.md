# OpenTTD-Stock: Roadmap and notes for AI assistants

Read this file first. It says what the project is, how it is built, what exists, what is planned and which mistakes have already cost a failed build.
Keep it up to date: when you finish or start something, change the lists below.

## 1. What this is
A mod of OpenTTD (the build uses OpenTTD 15.x, Windows MSVC, GitHub Actions `build-windows.yml`) that adds a finance layer to the game:
- **Trading Terminal** (`stock_gui.cpp`, `stock_base.*`, `stock_cmd.*`): company shares as candlestick charts, long/short positions, margin, SL/TP, pending orders.
- **Valuables** (`valuables.{h,cpp}`): a second topic of the Terminal, separate from the companies: gold (XAU), silver (XAG), platinum (XPT) and diamonds (XDI), traded like shares (candles of all timeframes, market and pending orders, SL / TP / trailing stop, leverage, trading wallets, swap, margin call). See the Done list.
- **Wallets** (`wallet_*`): cash plus trading wallets. Money can only go into a trading wallet from unborrowed cash.
- **Central Bank** (`central_bank*.{h,cpp}`): the only lender. Loans, daily interest, penalties, account log, account statement (ledger).
- **Past statements window** (`central_bank_gui.cpp`): 10 years, years on the left, the statement of the chosen year on the right.
- **Gold reserve** (`gold_reserve.{h,cpp}`): organic gold price, limited market stock, gold held by companies, backing ratio, credit standing.
- **Gold panel** (`gold_panel.{h,cpp}`): drawing and Buy/Sell actions. It is shown in the **operating profit graph window** (OpenTTD `graph_gui.cpp`), in the place of the graph; the Gold / Graph button in the title bar switches back to the graph. It is NOT in the Trading Terminal any more.
- **Buy gold window** (`gold_buy_gui.cpp`, window number 3 of `WC_CENTRAL_BANK`, widgets `WID_GB_*`): the Buy Gold button of the gold panel opens it (company vault - buy gold). Price per ounce, market state and stock, quantity with - / + / Max / 10 / 50 / 100 oz and click-to-type, value, fee (0 for now), total, usable (unborrowed) cash, cash after the purchase, Cancel / Confirm. All drawn in one panel; the rectangles come from `GbMakeLayout` (used for drawing and clicks). The GOLD badge opens the Gold Investment Types window, where the GOLD button of the header shows the price chart. `GB_USE_THAI` at the top switches Thai / English.
- **Game clock** (`game_time/`): the game has an HH:MM clock; days, candles and timeframes are derived from one number.
- Retail investors (`RetailMarketManager.*`), stock AI (`stock_ai.cpp`).

The repository is an **overlay**, not a full OpenTTD tree. `apply_overlay.py <openttd-tree>` copies the files in, registers commands, CMake files and strings, and patches some original files.

## 2. How to work in this repository
- Files live in the folder named in `FILES` of `apply_overlay.py` (for example `src/saveload/stock_sl.cpp`, `src/widgets/stock_widget.h`). **Edit those.**
  The old copies `src/stock_sl.cpp` and `src/stock_widget.h` were deleted; do not recreate them.
- A new source file needs entries in: `FILES`, `NEW_SOURCES` (CMake), and `STRING_FILES` if it has strings, all in `apply_overlay.py`.
- A new command needs: the name in `NEW_COMMANDS` (apply_overlay.py), a `DEF_CMD_TRAIT` in a header that `wallet_cmd.h` includes, and the function.
  Commands run on every client of a multiplayer game, so they must give the same result everywhere.
- A new saved value needs a record kind in `saveload/stock_sl.cpp` (`StockRecordKind`: used so far 0-43 (39 = SRK_FLEET, 40 = SRK_GOLD_NEWS, 41 = SRK_BANK_LOG, 42 = SRK_ZONE, 43 = SRK_ZONE_TAX); next free is 44 (the oil stock is not a new record, see the Done entry about oil); the policy emergency flag is bit 1 of ym of SRK_POLICY, the ledger line BankGoldOp is the last LedgerItem), written in `Save`, read in `Load`, and reset in `StockMarket::Reset` (`stock_base.cpp`).
- We cannot compile here. The only compiler is the GitHub Actions build. Read its log (the first error is the real one; later ones follow from it).

## 2b. OpenTTD files that the overlay patches in place
`apply_overlay.py` (`patch_graph_files`) inserts the gold panel into `src/graph_gui.cpp` and `src/widgets/graph_widget.h` of OpenTTD (marker: `GOLD_PANEL_PATCH`, widget numbers `WID_PHG_GOLD_*`).
It does NOT replace the files: it finds anchors (struct `OperatingProfitGraphWindow`, `_nested_operating_profit_widgets`, `WID_PHG_DETAILED_PERFORMANCE`, the `#include` of `widgets/graph_widget.h`) and reads the base class and the colour names from the file itself, so it fits the naming style of the OpenTTD version that is built. If an anchor is missing it stops with a clear error and writes nothing.
History: a first version replaced the whole files with copies of a newer OpenTTD (master) and failed to compile on 15.3 (`Colours::Brown`, `FontSize::Normal` do not exist there; 15.3 uses `COLOUR_BROWN`, `FS_NORMAL`, `WC_...`). Never copy whole OpenTTD files from another version.
The CI workflow (.github/workflows/build-windows.yml) also refuses to copy any file from `src/` of this repository that OpenTTD 15.3 already has, so files of OpenTTD must never be put in `src/` here.
The CI order is: checkout OpenTTD 15.3, `git apply stock-market.patch`, copy `src/` (no clashes allowed), `python3 mod/apply_overlay.py openttd`, build.

The operating profit graph is renamed **Gold Investment Types** (menu entry `STR_GRAPH_MENU_OPERATING_PROFIT_GRAPH` and caption `STR_GRAPH_OPERATING_PROFIT_CAPTION`) in every `src/lang/*.txt` by `patch_graph_window_name` in `apply_overlay.py` (the Thai file had its own text, so english.txt alone is not enough).

## 2c. Test tools (remove before a release)
Off at every start. In the OpenTTD console (key `` ` ``):
- `stock_dev on` / `stock_dev off`: switch the tools (`_stock_dev_tools`, `stock_dev.h`). While on, the Central Bank window shows a row of buttons `+1 hour`, `+1 day`, `+7 days`, `+30 days`, `+90 days` (`WID_CB_SKIP_*`, in a selection `WID_CB_SKIP_SEL`, plane 0 = buttons, plane 1 = nothing; the row is taken out of the layout with SZSP_NONE and ReInit, so no blank line while the tools are off).
- `stock_event` or `stock_event <0-19>` (needs `stock_dev on`): make a market news event at once (`stock_console.cpp`, `FireMarketEventNow`); 0-19 is the kind, see `MarketEventKind` in `market_events.h`.
- `stock_skip <days>` or `stock_skip <hours>h` (for example `stock_skip 30`, `stock_skip 12h`; at most 400 days): move the clock forward from the console. It needs `stock_dev on`.
- Both call `SkipGameMinutes` (`stock_console.cpp`) -> `GameTimeManager::AdvanceMilliseconds`, so every system that listens to the clock runs its events in time order: central bank interest, retail investors (daily), candles of all timeframes, gold price, the 90-day quarter close. Single player only (`_networking` is refused). Only the clock moves: the economy of OpenTTD does not, and vehicles do not catch up (see the vehicle time entry in Done), and the calendar date catches up one day per tick afterwards.
- A game day is 24 real minutes at normal speed, a quarter 36 real hours: without the skip, the retail investors (they need 30 days of price) and the dividends (they need 3 profitable quarters) cannot be tested.
- The commands are registered by `patch_console_file` in `apply_overlay.py`: one declaration and one call in `IConsoleStdLibRegister()` of `console_cmds.cpp` (marker `STOCK_CONSOLE_PATCH`). The code uses the console API of the files that the owner uploaded (`IConsole::CmdRegister`, handlers `bool Fn(std::span<std::string_view> argv)`, `IConsolePrint(CC_DEFAULT, ...)`); those files may come from master, so if the build fails in stock_console.cpp, compare with the real 15.3 `console_cmds.cpp`.
- To remove: delete `stock_console.cpp`, `stock_dev.h`, their entries in `FILES` and `NEW_SOURCES`, `patch_console_file`, the `WID_CB_SKIP_*` row and its cases in `central_bank_gui.cpp`, the enum entries and the `STR_CENTRAL_BANK_SKIP_*` strings.

## 3. Rules that already cost a failed build
1. **Comments after `///<` in `src/widgets/*_widget.h` must be plain ASCII with no double quotes.** The script API generator copies them into `script_window.hpp` as strings. A quote or Thai text there gives `C2001 newline in constant` followed by dozens of `enum type redefinition` errors.
2. All game maths is **integer** (no `double`, `pow`, `sqrt` in anything that changes game state). Floating point can desync multiplayer. `double` is fine for drawing and for parsing what the player types.
3. Money is `Money` (int64). Convert with `static_cast<int64_t>`. The gold price is kept in 1/100 of a money unit (`price_cents`).
4. Drawing: keep every `DrawString` inside `[left, right]` and skip lines that do not fit above `bottom` (see `DrawGoldLine`). Never draw outside the widget rectangle.
5. Fund isolation: nothing may be bought with borrowed money. Use `GetUnborrowedLiquidCash(company)` (central_bank.h).
6. Thai text is allowed in `.cpp` files (see `CbText("ไทย", "English")` in `central_bank_gui.cpp`), not in widget headers.
7. **Never put a copy of an OpenTTD file anywhere in this repository** (not in `src/`, not in a `replace/` folder). The build step "Add stock market source files" fails with `src/<file> already exists in OpenTTD 15.3 ... refusing to overwrite it`, and a copy made from another OpenTTD version does not compile on 15.3 (names differ: `Colours::Brown` vs `COLOUR_BROWN`). Changes to OpenTTD files are made in place by `apply_overlay.py` (anchors, see section 2b) or by `stock-market.patch`.
9. **Never `using namespace citizengold;`** in a game file: OpenTTD has its own `Order`, `Style`... and the name becomes ambiguous (C2872). Write `citizengold::` (the standalone test may use it).
8. Do not mention or rely on window numbers twice: `WC_CENTRAL_BANK` uses number 0 (bank), 1 (statement), 2 (past statements), 3 (buy gold), 4 (policy), 5 (payroll news), 6 (market news), 7 (cargo prices), 8 (oil market), 9 (zones map), 10 (headquarters gate), 11 (zone taxes). Zone borders in the game view: `zone_borders.cpp` (console `zone_lines on|off`, hooks `patch_zone_borders` / `patch_zone_status` in apply_overlay.py).
10. **In a `.cpp` file (not in a header) never use what `safeguards.h` bans: `std::to_string`, `stoi`, `stol`, `malloc`, `strdup`, `sprintf` ...** `safeguards.h` is the last include of every `.cpp` and defines these names as `SAFEGUARD_DO_NOT_USE_THIS_METHOD`; the use gives `no member named 'SAFEGUARD_DO_NOT_USE_THIS_METHOD' in namespace 'std'`. Use `fmt::format("{}", x)` and `std::from_chars`. Headers are safe because they are included before it (found by `check_build.sh`, `oil_market_gui.cpp`).
## 4. Gold system (current design)
**The price is a random walk like a real market (owner 2026-10-28; before: a glide of 5% of the way to a target per day).** State = `price_cents` (saved) and `last_level_cents` (saved in `SRK_GOLD_NEWS` v2). Every 2 game minutes `UpdateGlide` makes ONE step: (1) a chance move `goldmath::StepNoisePpm` (hash of seed and game minute; 0.8% a day in a normal spell, calm 0.6x .. stormy 2.2x in blocks of 15 days, about 16% a year), (2) the price follows the CHANGE of the level at once by the same ratio (`level` = `ComputeTargetCents`, `price = price x level / last_level`): news, trades of companies / citizens / the bank, inflation, cash, stock all move the price in the same minute. Once a day `UpdateDaily` pulls the price 0.5% of the gap towards the level (`goldmath::REVERT_PPM_PER_DAY`, half of a gap in about 4.5 months), rebalances the stock, pushes the price into the chart (`history_cents`) and fades the demand pressure 3%. The slow bull / bear waves are NOT part of the level any more (`GoldReserveManager::PRICE_USES_CYCLE` = false). `MARKET_GOLD_REAL_SHOCK` is false: the news already moves the level through `pressure_ppm`, a second shock would count it twice (`ApplyShock` stays, unused). `day_shift_cents` is always 0 (kept in the record). Level (`ComputeTargetCents`) = base price (2000) x:
1. inflation of the game (`_economy.inflation_prices`),
2. (OFF since 2026-10-28: `PRICE_USES_CASH = false`) cash in circulation against what inflation explains (baseline cash x inflation; half of the difference counts; loans make cash bigger). It used to be compared with the plain baseline, which counted inflation twice (the pay of OpenTTD grows with inflation, so the cash does too),
3. demand: the NEWS and the policy (`pressure_ppm`, fades 3% a day) plus the impact of the TRADES (`impact_ppm`, fades in about 1.6 game days; since 2026-10-28), together max +-30% (`GetDemandPressurePpm`),
4. scarcity: the market has a limited stock (`MARKET_STOCK_START` = 1000 tons = 32,151,000 oz). Buying takes from it, selling gives back. Half the stock left = price x2, capped at x4,
5. safe haven: when the summed company value of the map falls from one quarter to the next, up to +20%.
Limit: the level stays near anchor = base price x inflation. Up to 25% away (`TARGET_SOFT_DEV_PPM`) it is free, beyond that it moves a third as fast, and it is never more than 50% away (`TARGET_MAX_DEV_PPM`), above or below (raw +100% gives +50%, raw -50% gives -33%). (Changed 2026-10-25: scarcity is applied after the limit, see Done: Gold start stock 1000 tons.) `GoldReserveManager::GetFactors()` returns every part (`GoldFactors`); the console command `gold_factors` prints them (read only, no `stock_dev` needed).
The cash that the level sees is an AVERAGE over about 7 game days (`cash_avg`, `goldmath::SmoothedCash`, one step every 2 minutes, saved in `SRK_GOLD_NEWS` v3), because the real cash of the companies jumps with every income and expense. Tune with `stock_dev` / `stock_skip`: `goldmath::CASH_SMOOTH_DAYS`, `STEP_SIGMA_DAY_PPM`, `REVERT_PPM_PER_DAY`. Orders of companies are NOT a main cause of jitter (100 oz = 0.5% of pressure with `DEPTH_OUNCES` 20,000; citizens are 25 times deeper), so depth and the 3% fade were not changed.

Backing ratio = value of the gold of the CENTRAL BANK / notes in circulation (`GetNotesInCirculation`). The central bank starts with gold worth 80% of the cash (`START_BACKING_PERCENT`). Credit standing: C < 40%, B, A (60%), AA (85%), AAA (100%) (`TIER_*_BP` in gold_reserve.h); the game starts in A. The bank buys below 60% and sells above 100%, at most 0.5% of its own gold a day (`BankGoldDailyCapOz`).
Buy is paid from unborrowed liquid cash only. No spread, no commission yet. Gold is not a position: no margin, no SL/TP.
Source of gold: a world market with a limited stock. Gold delivered from mines adds to it, but limited (yield falls as the stock fills, daily limit, cap 1.5 x start, see Done: Gold from mines limited).
